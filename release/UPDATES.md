# Выпуск обновления RuЭкран

Текущая alpha.6 и более старые клиенты не содержат канал RuЭкран: для перехода на механизм обновлений нужна одна обычная установка новой сборки.

Новый клиент проверяет https://ruekran.ru/updates/windows-x86.json при запуске главного окна и каждые 6 часов. Новая версия отображается слева внизу. Клиент не загружает и не запускает выпуск без нажатия «Обновить». ID, пароли и список компьютеров в запрос не включаются.

Метаданные подписаны отдельным Ed25519-ключом. Открытый ключ — source-x86/res/update-public-key.bin. Закрытый ключ хранится вне репозитория и сайта, в DPAPI текущей Windows-учётной записи: %LOCALAPPDATA%/RuEkranAdmin/update-signing-key.bin. Его нельзя удалять или заменять для обычного выпуска. Потеря ключа лишит возможности подписывать обновления для уже выданных клиентов; требуется защищённая резервная копия ключа и среды его восстановления. Простое копирование DPAPI-файла на другой компьютер не гарантирует восстановление.

Порядок выпуска:

1. scripts/build-universal.ps1 резервирует следующий номер. Для повторной сборки того же выпуска — -Rebuild.
2. scripts/package-universal.ps1 готовит единый EXE и соответствующие исходники. scripts/verify-universal.py проверяет упаковку.
3. scripts/sign-update.py проверяет Windows-версию EXE и формирует подписанный windows-x86.json. Для подписи нужны локальный модуль admin/vault.py и cryptography; закрытый ключ не нужен для компиляции клиента.
4. Штатный клиент поддерживает проверку без установки: RuEkran.exe --verify-ruekran-update windows-x86.json release.exe. Неверная подпись, размер, SHA-256 или откат отклоняются.
5. Сначала разместить EXE по неизменяемому адресу https://ruekran.ru/releases/RuEkran-Windows-x86-x64-N.exe, соответствующие исходники и уведомления. N — глобальный build из version.json. Уже опубликованный адрес выпуска не перезаписывать.
6. Выполнить python scripts/sync-website-version.py: подпись канала и EXE проверяются до записи версии в подпись кнопки сайта и SoftwareApplication. Разместить обновлённый index.html вместе с новым выпуском, сохранив прежний в закрытой копии.
7. После HTTPS-проверки файлов атомарно заменить updates/windows-x86.json. Feed не должен указывать на ещё не размещённый файл. Предыдущие файлы сохранить в закрытой резервной копии.

Клиент принимает только подписанные сведения своего формата, HTTPS без отключения проверки сертификата, точный адрес своего канала, ограниченный размер и более новый номер сборки. Перед установкой сверяются размер и SHA-256. Ошибка загрузки оставляет действующую программу на месте; пользователь может повторить попытку.

Установленная версия использует штатный --update с подтверждением UAC при необходимости; после завершения открывается установленный клиент. Текущие сеансы могут прерваться. Обход UAC не реализуется.

Portable-версия заменяет исходный единый EXE после проверки, ждёт завершения старого главного процесса и запускает новую версию. Папки распаковки разделены по версиям, чтобы не перезаписывать запущенный EXE. Если исходный файл недоступен для записи или программа запущена из распакованной папки без исходного wrapper, показывается ошибка, установка в систему не запускается. Старые папки распаковки автоматически не удаляются.

Если ключ создавался из упакованной среды Windows, его фактический путь может находиться под %LOCALAPPDATA%/Packages/<package>/LocalCache/Local/RuEkranAdmin/. Проверяйте фактический путь через resolve() в среде сборки и сохраняйте весь Windows-профиль, включая Packages. Перенос сохранённого входа панели в обычный профиль переносит только credentials.bin; ключ подписи обновлений и server-backup.bin не перемещаются.
